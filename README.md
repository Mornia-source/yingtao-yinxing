# 樱桃音形

自制 Rime 中州韵方案：自然码双拼 + 98五笔首末字根形码。

## 编码规则

- **单字**：自然码双拼全码（2位，不含辅助码） + 98五笔该字首位字根 + 末位字根（2位，不含末笔识别码）。例：廷=tytp，啊=aakk，我=woty，全=qrwg。双拼2位一打完，同音字就已经按字频排好队出现在候选里了（比如打"ui"就能看到 是/时/事/使/式……），不用非等形码也打完才能选字；形码留给需要精确定位某个字的时候用。
- **二字词**：简码 = 前字前两位 + 后字首位（3位）；全码 = 前字前两位 + 后字前两位（4位）；**精确码 = 全码 + 前字首字根 + 后字首字根（6位）**。例：简单=jmd/jmdj/jmdj**tu**，时间=uij/uijm/uijm**ju**，银行=ynh/ynhh/ynhh**qt**。词组一律从3位编码起，2位编码专属于单字双拼（见上一条），这样双拼2位刚打完时，候选里只会出现同音单字，不会被词组抢占。
- **单键硬性首选**：只按一个字母时，第一候选固定为下表的字，不受词频和调频影响：`q去 w我 e二 r人 t他 y一 u是 i出 o哦 p平 a啊 s三 d的 f发 g个 h和 j就 k可 l了 z在 x小 c才 v这 b不 n你 m没`。其余编码照常按词频排序、并保留 user_dict 智能调频。
- **三字词**：全码 = 前两字首码 + 第三字前两位；简码 = 三字首码。例：不知道=bvdk/bvd，非常好=fihk/fih。
- **四字词**：四字首码。例：妙不可言=mbky。
- **五字及以上**：前三字首码 + 末字首码。例：踏破铁鞋无觅处=tpti。
- **ü 韵母 u/v 都能打**：j/q/x/y 后面的"u"实际是"ü"（续xù、语yǔ、去qù、句jù……），标准双拼用 v 表示，但因为 x/j/q/y 从不会真的和"u"这个韵母搭配，所以打 u 或 v 都能选中同一个字/词——继续=jixv 或 jixu 都行，粤语=ytyv 或 ytyu 都行。有简码的词全码依然保留、不会被简码顶掉。
- **零声母 an/en/ai/ei/ao/ou 直接按字面打**：这几个韵母本身拼音拼写就正好是2个字母，不再套"重复声母、压缩韵母"那一套，直接按字母打——按=an，安=an，爱=ai，诶=ei，奥=ao，欧=ou。（a/e/o 单独或带 ng 的 a/ang/e/eng 仍然需要重复首字母来腾出韵母键位，比如 啊=aa、昂=ah。）

## 安装方法

1. 安装 [小狼毫 Weasel](https://github.com/rime/weasel/releases)（Windows，且需要支持 `lua_filter` 的构建，比如98五笔版小狼毫自带的那种）或其他支持 lua 插件的中州韵前端。
2. 把本目录下的文件复制到 Rime 用户目录（Windows 一般是 `%APPDATA%\Rime`）：
   - `yingtao.schema.yaml`
   - `yingtao.dict.yaml`
   - `yingtao_chars.dict.yaml`
   - `yingtao_words.dict.yaml`
   - `lua/char_priority.lua`（复制到用户目录下的 `lua` 子文件夹，没有就新建）
3. 编辑用户目录下的 `default.custom.yaml`（没有就新建），加入：

   ```yaml
   patch:
     schema_list:
       - schema: yingtao
   ```

4. 右键托盘图标"重新部署"。**注意**：小狼毫的"重新部署"只会重新编译码表文件，正在运行的 WeaselServer 进程不一定会重新加载编译结果；如果部署后候选看起来还是旧的，需要手动重启一次 WeaselServer 进程（或注销/重启电脑）。

## 数据来源与生成方法

**单字**

- **98五笔字根参考（去末笔识别码）**：用户自行整理的"通用规范汉字8105字"参考表，每个字对应的98五笔码已手动去掉末笔识别码、只保留真实字根序列，是单字形码的首选数据源（`sources/wubi98_noident_8105.txt`）。
- 单字的拼音与字频：[iDvel/rime-ice](https://github.com/iDvel/rime-ice) 的 8105 常用字表。
- 官方98五笔全码：[lotem/rime-wubi98](https://github.com/lotem/rime-wubi98)、汉字结构拆分：[hanzi-chai/pychai](https://github.com/hanzi-chai/pychai) —— 仅作为上面参考表覆盖不到的极少数生僻字（约32个）的备用近似算法。

**词组**（v2.0 起换用 openfly 词表重建）

- **词表**：[amorphobia/openfly](https://github.com/amorphobia/openfly)（词库开源的小鹤音形 Rime 配方）的 `primary`(首选) / `secondary`(次选) 词表，约 5.3 万条精选多字词，**外加 rime-ice 里词频 ≥2000 的双字词约 1750 条**，共约 5.5 万词。**只取「词本身」和它所在的层级，小鹤自己的编码一概不用**——樱桃音形的编码全部由本文档「编码规则」一节的规则现算。
  > openfly 已停更（最后更新 2024-09）。但实测下来它的价值不在「新」而在「精选、量小」——真正长期维护的中文词库是 [rime-ice 雾凇拼音](https://github.com/iDvel/rime-ice)（我们一直在用它查词频）。小鹤官方词库本身是闭源且禁止反编译的，社区里还在维护的所谓「小鹤词库」方案（rime-fast-xhup、rime-crane 等）用的其实都是雾凇的词库，只是套了小鹤的编码规则。所以「小鹤重码少」是**编码方案 + 词表精简**的功劳，不是词库本身有什么魔法。
- **注音**：[pypinyin](https://github.com/mozillazg/python-pinyin)，按整词注音，能正确区分多音字（银行 yin-hang、重庆 chong-qing、会计 kuai-ji、音乐 yin-yue 均已验证）。
- **词频**：openfly **没有任何词频/权重字段**（15 个词典文件全部只有「词 + 小鹤编码」两列，优先级靠文件分层和行序表达，而那个行序是按小鹤自己的编码排的，对我们没用）。所以 rime-ice 的 `base`/`chengyu` 词库降级为**只查词频的辅助表**，不再决定收录哪些词。openfly 的词有 90.2% 能在 rime-ice 里查到词频，剩下约 5000 条给一个偏低的默认值（100，约等于 rime-ice 词频的下四分位），保证能打出来但不会盖过真正的常用词。次选词整体再乘 0.3 降权，体现 openfly 的 primary/secondary 分层。

**生成脚本**

`../build/` 下的 Python 脚本可重新运行以更新码表：`shape.py`（形码计算）、`zrm.py`（自然码双拼算法）、`tier_boost.py`（码长分档权重）、`gen_chars.py` / `gen_words.py`（生成码表）。`../sources/` 存放脚本依赖的原始数据快照。

生成词库需要 pypinyin：

```bash
pip install pypinyin
```

## 已知局限

单字形码现在以用户提供的"98五笔去识别码"参考表为准（覆盖 8105 字表中的 8494 字，直接取参考表里字根序列的首字母+末字母，结果是精确的，不再依赖猜测）。只有约32个不在这份参考表里的生僻/异体字（如 車、卻、咲、牠等，本来就不属于通用规范汉字表），才会退回到"拆字库交叉验证 + 官方全码首尾近似"的旧算法，可能存在少量偏差；还有3个极生僻扩展汉字查不到五笔码，未收录进单字表。

如果后续发现某个字的形码不对，最快的办法是直接在 `yingtao_chars.dict.yaml` 里手动改那一行的码；如果是参考表本身就没有的生僻字，也可以在 `build/shape.py` 的 `CHAR_SHAPE_OVERRIDE` 里加一条手动修正。

## 编码位数越少优先级越高

这条规则由两套机制配合完成：

1. **`build/tier_boost.py`（词典权重加成）**：候选自身编码位数分三档加成——2位（单字双拼）+1亿，3位（词组简码）+5千万，4位（全码）不加成，同档内再按词频排序。这样"2位单字 > 3位简码 > 4位全码"这个优先级本身就写进了词典权重里。这个文件里还有一份 `PRIORITY_OVERRIDES` 手动名单，用来给个别撞码撞得比较厉害的固定搭配（比如编码`womf`固定优先"我们"）单独加一大截权重兜底，不依赖下面的排序过滤器。
2. **`lua/char_priority.lua`（候选过滤器）**：Rime 的补全(completion)候选是按编码在字根树里的先后顺序枚举出来的，并不会跨编码统一按词典权重重排——这意味着只靠第1条加权重，"的"也不一定能排到"掉落"前面。这个过滤器在候选队列最前面一小段（默认20个）里，按候选的 `quality` 重新排序，让第1条设好的权重真正体现到候选顺序上。**这里踩过坑**：直接对候选调用 `table.sort` 出过一次问题——候选流里偶尔混入 `quality` 不是普通数字的候选，导致排序中途出错但已经做了部分交换，候选顺序反而更乱。现在的写法是先把所有候选的 `quality` 取到一个数组里逐个校验，校验不通过就直接放弃排序、原样透传，确保任何情况下都不会比"完全不排序"更差。

## 双字词 6 码精确码的由来

双字词打 4 码全码后如果还有重码，可以**继续打 2 位形码**（前字首字根 + 后字首字根）精确定位，不需要任何引导符。实测重码率（雾凇全量 12.4 万双字词）：

| 取码方式 | 唯一码率 | 最大重码 |
|---|---|---|
| 4 码全码（不加形码） | 25.7% | 34 |
| **6 码：字1首根 + 字2首根** | **93.5%** | **6** |
| 6 码：字1首根 + 字2末根 | 91.7% | 5 |
| 6 码：字1末根 + 字2末根 | 89.0% | 6 |
| 5 码：只加 1 位 | 66% | 14~16 |

选「两个字都取首根」：区分度最高，规则也最统一好记（一条规则而不是两条），并且和五笔词组规则（`AaAbBaBb`，都从头取）一致。分析脚本见 `build/analyze_2char.py`。

**为什么不需要 `;` 引导符**：librime 的 `auto_select` 有两条独立路径——`AutoSelectUniqueCandidate` 要求**候选恰好只有 1 个**才自动上屏（`seg.menu->Prepare(2) == 1`），而 `AutoSelectAtMaxCodeLength` 按 `max_code_length` 触发且不管候选数量。所以把 `max_code_length` 抬到 6、`auto_select_pattern` 写成 `^[a-z]{4}$|^[a-z]{6}$` 之后：4 码唯一 → 直接上屏（本来也不需要 6 码）；4 码撞车 → 不上屏，可以继续打第 5、6 码；6 码唯一 → 上屏。天然自洽。

**扩词的取舍**：4 码唯一率随词表规模断崖式下跌——openfly 3.24 万词时 93.4%（最大重码 3），加雾凇词频≥2000 后 88.0%（最大重码 9，一页仍装得下），≥1000 掉到 81.7%，全量加会崩到 25.7%（最大重码 34）。当前取 ≥2000 这个甜点。阈值在 `build/gen_words.py` 的 `EXTRA_2CHAR_MIN_FREQ`。

## 智能分词 / 长句连续输入 / 四码顶字

- `translator/enable_sentence: true`：允许词与词之间不用分隔符直接连打，输入法会自动按码表做分词组合成整句。
- `speller/auto_select` + `auto_select_pattern`：编码唯一时自动上屏（4 码或 6 码），有重码时不会被提前打断，可以继续挑候选或续打。
- `engine/filters` 里 `uniquifier` 负责去重——双字词同时有 4 码和 6 码词条，打 4 码时它自己的 6 码会作为补全候选再冒出来一次。
- 三个开关（中西文、半全角、繁简）都加了 `reset: 0`，避免继承别的方案里的全角/繁体状态，导致回车提交出来的字母变成全角。

## 中文标点

标点映射直接写死在 `yingtao.schema.yaml` 的 `punctuator` 段里，不再 `import_preset`——因为同一个 Rime 用户目录下别的方案（wubi98_ci 等）共用 `punctuation.yaml`，写死可以避免互相干扰。

中文模式（`half_shape`）下符号键的输出：

| 键 | 输出 | 键 | 输出 | 键 | 输出 |
|---|---|---|---|---|---|
| `!` | ！ | `$` | ￥ | `^` | …… |
| `(` `)` | （） | `_` | —— | `[` `]` | 「」（可翻页选【】） |
| `\` | 、 | `:` | ： | `;` | ； |
| `'` | ‘’ | `"` | “” | `<` `>` | 《》 |
| `,` | ， | `.` | 。 | `?` | ？ |
| `/` | 、 | `{` `}` | 『』 | | |

`@ # % & * - + = |` 保持原样输出半角，符合中文写作里这些符号本来就用半角的习惯。切到西文模式（`ascii_style`）时全部输出半角原字符。

## 待办

「先按 `;` 再按 `i` 快速删除刚上屏的内容、`;;` 或 `;`+回车输入字面分号」这个功能还没做——它需要新写一个按键处理器（processor），比候选过滤器复杂、风险也更高，留待后续。目前 `;` 直接上屏 ；。

另外，个别口语化短语（如"手头紧"）词库里可能没收录，可以自己在 `yingtao_words.dict.yaml` 里按同样规则追加。
